# Learning on generalized maps: dart convolutions with orbit pooling

This is a self-directed project, which I used to learn the fundamentals of deep learning in a
setting I already knew well. It starts from a reproduction of **MeshCNN**
(Hanocka et al., SIGGRAPH 2019) and builds a neural network that operates on **generalized maps**
(G-maps), the combinatorial structure used in topology-based geometric modelling. The network
computes on **darts** and pools information over **orbits** (vertices, edges, faces). It is
designed to extend beyond triangle meshes to general combinatorial maps; so far it has only
been evaluated on triangle and mixed mesh classification (SHREC-16).

**Main result.** On SHREC-16 classification, under an identical protocol, the dart network with
orbit pooling matches my reproduction of MeshCNN: 85.6 % vs 85.6 % mean test accuracy over
4 seeds, each model winning on 2 seeds. Its layers are equivariant to any renumbering of the
darts by construction, without hand-made symmetrisation.

## Background: from MeshCNN edges to G-map darts

MeshCNN convolves over **edges**: each edge of a closed triangle mesh has 4 neighbouring edges,
whose order is made unambiguous by a hand-crafted symmetrisation (`a+c, |a-c|, b+d, |b-d|`).

A **2-G-map** describes a surface with **darts**, one per (vertex, edge, face) incidence, and
three involutions:

| involution | keeps | changes |
|---|---|---|
| α₀ | face, edge | vertex |
| α₁ | face, vertex | edge |
| α₂ | vertex, edge | face (fixed point on a boundary) |

Geometrically, a dart is a triangle of the barycentric subdivision, and αᵢ crosses the side of that
triangle opposite to its corner of dimension i. Cells are **orbits**: a vertex is ⟨α₁,α₂⟩, an edge is
⟨α₀,α₂⟩ and a face is ⟨α₀,α₁⟩. Because the neighbours of a dart are labelled canonically (one per
dimension), a convolution over darts needs no symmetrisation, and the same code applies to any
dimension (one more involution per dimension).

## Method

- **`DartConv`** (`gmapnet/dartconv.py`): for each dart, a shared linear map of
  `[x_d, x_α₀(d), x_α₁(d), x_α₂(d)]`.
- **Orbit pooling** (`gmapnet/orbitconv.py`): each layer also reads, for chosen orbit types 𝒪, the
  mean of the features over the dart's orbit, implemented as a scatter (sum per orbit) followed by a
  gather (copy back to the darts):

  `x'_d = b + W_self x_d + Σᵢ Wᵢ x_αᵢ(d) + Σ_{O∈𝒪} [ U_O mean_O(x)(d) + V_O disp_O(x)(d) ]`

- **Orbit dispersion**: the mean of |x − orbit mean| over the orbit. On a pair {a, c},
  (mean, dispersion) = ((a+c)/2, |a−c|/2), which is exactly MeshCNN's symmetrisation; dispersion
  generalises it to orbits of any size. Together with the mean it is a complete invariant of
  unordered pairs, whereas the mean alone is not.
- **Per-dart LayerNorm** before each ReLU. Without it, a whole layer of ReLUs died during training
  (0 % active units in layer 2 after ~150 steps): from layer 2 on, inputs (ReLU outputs, orbit means
  and dispersions) are all non-negative, so pre-activations are not centred.

The 5 MeshCNN edge features are recovered exactly from orbit features, as words in the
involutions (`gmapnet/features.py`, checked against `src/mesh.py` in the tests).

## Results

Protocol for every number below: SHREC-16 (30 classes, 16 training and 4 test meshes per class);
4 training meshes per class are held out for validation (12 / 4 / 4); the epoch is chosen on
validation and test accuracy is reported at that epoch. The seed also fixes the validation split, so
comparisons are made seed by seed. All tables are regenerated by `python results/summarize.py` from
the raw logs in `results/`.

### Main comparison (seeds 0–3)

| model | params | test per seed | test (mean ± sd) |
|---|---|---|---|
| OrbitCNN, edge + face + vertex, LayerNorm | 297k | 83.3 / 85.8 / 77.5 / 77.5 | 81.0 ± 4.2 |
| **OrbitCNN, edge + face + vertex, LayerNorm + dispersion** | 421k | 86.7 / 90.0 / 80.0 / 85.8 | **85.6 ± 4.2** |
| **MeshCNN reproduction** (no MeshPool, no augmentation) | 215k | 88.3 / 88.3 / 75.8 / 90.0 | **85.6 ± 6.6** |
| control: OrbitCNN + LayerNorm, widened to 417k params | 417k | 82.5 / 81.7 | 82.1 ± 0.6 |

Dispersion improves test accuracy on each of the 4 seeds (+4.6 points on average). The widened
control has as many parameters as the dispersion model and does not improve, so the gain is not
explained by capacity.

### Comparison for mixed meshes (seeds 0-3)

OrbitCNN E,F,V + LayerNorm + dispersion; each triangle mesh is turned into a mixed triangle/quad
mesh by `gmapnet/quadify.py` (same shapes, same splits).

| mesh | test per seed | test (mean ± sd) | val (mean) |
|---|---|---|---|
| triangles (re-run) | 86.7 / 90.0 / 82.5 / 85.8 | **86.2 ± 3.1** | 86.9 |
| mixed, min_dihedral = 160° (66 % of triangles merged) | 80.0 / 87.5 / 87.5 / 86.7 | **85.4 ± 3.6** | 82.5 |
| mixed, min_dihedral = 140° (79 % of triangles merged) | 90.8 / 90.0 / 86.7 / 94.2 | **90.4 ± 3.1** | 90.4 |

Results obtained on the mixed meshes with a strong filter (min_dihedral = 160°) are on par with
those on the triangle meshes. With a slightly weaker filter (min_dihedral = 140°), the results are
promising (at least on par on each seed) but would require more seeds to be established. Finally,
the triangle re-run reproduces the original results exactly on 3 seeds out of 4; the difference on
seed 2 (82.5 vs 80.0) probably comes from the original runs having been run in parallel.

### Which orbit types matter (no normalisation, seeds 0–1)

| orbits pooled | params | test per seed | test (mean ± sd) |
|---|---|---|---|
| none (plain DartConv) | 173k | 55.0 / 65.8 | 60.4 ± 7.7 |
| edge ⟨α₀,α₂⟩ | 214k | 57.5 / 73.3 | 65.4 ± 11.2 |
| face ⟨α₀,α₁⟩ | 214k | 70.0 / 74.2 | 72.1 ± 2.9 |
| vertex ⟨α₁,α₂⟩ | 214k | 75.0 / 75.0 | 75.0 ± 0.0 |
| edge + face + vertex | 296k | 80.8 / 79.2 | 80.0 ± 1.2 |
| control: none, widened to 294k params | 294k | 50.8 / 56.7 | 53.8 ± 4.1 |

The order vertex > face > edge was predicted before the runs by a receptive-field argument: pooling
over an orbit helps when the orbit reaches darts that a convolution cannot see in one step, and the
farthest dart of an orbit is 2 steps away for an edge, 3 for a face and deg(v) (about 6 here) for a
vertex. Only α₀ moves across the surface; α₁ and α₂ turn around a vertex. The same order holds on
both seeds; with 2 seeds this is indicative, not conclusive.

### A symmetry defect found in my own reproduction

Analysing the 4 darts of an edge as the Klein group {id, α₀, α₂, α₀α₂} showed that my initial
reproduction ordered the 4 neighbouring edges by **vertex index**, so MeshConv depended on how the
vertices were numbered. The original MeshCNN orders them by face orientation, which leaves only the
180° rotation α₀α₂ for the symmetrisation to absorb. Fixing the convention in my reproduction
(`src/mesh.py`, now tested against vertex renumbering in `tests/test_meshconv.py`) raised its accuracy
from 77.1 % to 88.3 % (seeds 0–1). All MeshCNN numbers above use the corrected version.

### Transfer between mesh representations (without retraining)

The model kept at the best-validation epoch is tested, without retraining, on the test meshes of
another representation (features standardised with the statistics of the training representation).

| trained on | tested on | test per seed | test (mean ± sd) |
|---|---|---|---|
| triangles | mixed 160° | 48.3 / 27.5 / 7.5 / 64.2 | **36.9 ± 24.7** |
| triangles | mixed 140° | 39.2 / 22.5 / 7.5 / 63.3 | **33.1 ± 23.9** |
| mixed 160° | triangles | 66.7 / 20.0 / 48.3 / 40.8 | **44.0 ± 19.3** |
| mixed 160° | mixed 140° | 80.0 / 84.2 / 85.0 / 85.0 | **83.5 ± 2.4** |
| mixed 140° | triangles | 50.0 / 45.8 / 22.5 / 26.7 | **36.2 ± 13.7** |
| mixed 140° | mixed 160° | 90.0 / 89.2 / 86.7 / 91.7 | **89.4 ± 2.1** |

To test how much the learned classifier depends on the combinatorial support, each trained model
was evaluated on other representations of the same test shapes: a change of filtering criterion
between mixed meshes, and the change from triangle meshes to mixed meshes and back.
The transfer between mixed and triangle meshes fails (33 to 44 % on average, with a large spread
across seeds): the network relies heavily on the combinatorial structure of the meshes it was
trained on, and is not invariant to this change of discretization (the topology of the shapes is
unchanged). The transfer between the two mixed variants works (−1 to −2 points), which suggests that
training on several representations at once could make the network more robust.

## Limitations

- One small dataset (SHREC-16, 480 training meshes); 4 seeds for the main comparison, 2 for the
  ablation. Test sets have 120 meshes, so one mesh is about 0.8 points.
- The comparison is against my **reproduction** of MeshCNN without MeshPool or data augmentation,
  under my protocol. These numbers are not comparable to those reported in the MeshCNN paper.
- The dart network costs about 2× the parameters and roughly 7× the training time of the MeshCNN
  reproduction (D = 3000 darts vs E = 750 edges per mesh).
- Only closed, consistently oriented triangle and mixed meshes have been tested; the extension to
  general cells and higher dimensions is designed in, not demonstrated.
- The mixed meshes are obtained by merging pairs of SHREC-16 triangles into quads (nearly flat and
  convex by construction), not by remeshing: native quad-dominant meshes remain to be tested.

## Transparency: use of an AI assistant

I used an LLM assistant (Claude) as a tutor throughout this project. It wrote the test harnesses and
experiment scripts, helped me find bugs and write the documentation, and pointed out the Klein-group
symmetry defect in my MeshCNN reproduction. I implemented the core components (G-map construction,
orbit features, DartConv, orbit pooling and dispersion, the MeshCNN reproduction); design choices such
as reading darts as barycentric triangles and pooling over a lattice of orbit types are mine. I can
explain and justify every component of this repository.

## Repository layout

```
src/                 MeshCNN reproduction
  mesh.py            edge topology (gemm) and the 5 invariant edge features
  layers.py          MeshConv
  model.py           MeshCNN classifier (MeshConv + global max pooling)
  dataset.py         SHREC-16 loader (edges)
  train.py           quick full-split training run
gmapnet/             learning on G-maps
  gmap.py            triangle mesh -> 2-G-map, orbits, orientability test
  features.py        orbit features; MeshCNN features recovered as words in the involutions
  dartconv.py        DartConv
  orbitconv.py       orbit mean / dispersion, OrbitDartConv, OrbitCNN classifier
  quadify.py         triangle mesh -> mixed triangle/quad mesh (greedy merging of flat pairs)
  data.py            SHREC-16 as G-maps, validation split
  train_orbit.py     one OrbitCNN run (configuration, seed)
  train_meshcnn_protocol.py   the MeshCNN reproduction under the same protocol
  run_experiments.py re-runs every experiment of this README
  diag_relu.py       dead-ReLU diagnostic
results/             raw run logs (.jsonl) and summarize.py
tests/               unit tests (G-map axioms, invariances, oracles)
overfit_demo.py      sanity check on a toy task
```

## Usage

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows; on Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Data: the SHREC-16 classification split distributed with the original MeshCNN repository
(<https://github.com/ranahanocka/MeshCNN>), placed as `data/shrec_16/<class>/{train,test}/*.obj`.

```bash
python -m tests.test_gmap                      # each file in tests/ runs the same way
python -m gmapnet.train_orbit E,F,V+d+n 0      # one run: orbits, dispersion, LayerNorm, seed 0
python -m gmapnet.run_experiments              # all runs of this README (several hours on CPU)
python results/summarize.py                    # tables from the raw logs
```
